# DESIGN: 東京23区 子連れイベント AIガイド

## 1. サイトの役割

新サイトは「検索条件を入れてイベントを探すアプリ」ではなく、AIが東京23区を横断探索して週末の子連れ候補を編集・公開する静的サイトとする。

利用者は、AIが収集済みの母集団を以下で確認できる。

- 全件
- 23区別
- キーワード
- 子連れ適性 A / B / C
- 屋内 / 屋外
- 無料 / 有料 / 要確認
- 予約要否

初期実装で必須とするのは「23区別」「キーワード」。その他はデータ項目を先に持ち、UIは段階追加可能とする。

## 2. 探索単位

探索は必ず23区を明示的に1区ずつ処理する。全体検索だけで「23区を見た」と扱わない。

東京23区:
千代田区、中央区、港区、新宿区、文京区、台東区、墨田区、江東区、品川区、目黒区、大田区、世田谷区、渋谷区、中野区、杉並区、豊島区、北区、荒川区、板橋区、練馬区、足立区、葛飾区、江戸川区。

各区について、次の層を順番に確認する。

1. 区公式イベント・観光・子育て・文化施設
2. 東京都・都立施設・公園・博物館等の公式情報
3. 子育て/イベント媒体
4. 商業施設・文化施設・鉄道・スポーツ等の公式情報
5. Web横断検索（区名＋日付＋親子/子ども/祭り/ワークショップ等）

探索結果は `coverage.wards[]` に記録し、各区で `status=checked` にならない限り本番公開を許可しない。

## 3. 候補抽出

「子ども向け」と明記されたイベントだけに限定しない。

候補に含める例:
- 祭り、縁日、地域フェス
- 鉄道・乗り物
- 動物・水族館・自然
- 科学・防災・消防・警察等の体験
- ワークショップ
- スタンプラリー
- キャラクター
- 食イベントのうち子連れ参加が現実的なもの
- 展示・舞台・スポーツのうち年齢条件が合うもの

除外候補:
- 明確な成人限定
- 深夜主体
- 子どもの入場不可
- 開催日が対象週末と重ならない
- 開催地が東京23区外
- 公式または信頼できる開催根拠を確認できない

## 4. 子連れ適性

`family_fit.grade` を A / B / C で保持する。

- A: 幼児・小学生向け要素が明確、親子参加を強く推奨できる
- B: 子連れ参加可能性が高いが、主目的が子ども向けとは限らない
- C: 条件付き。年齢、混雑、内容、時間帯等の注意が必要

`family_fit.reason` に短い根拠を必須化する。

## 5. データモデル

イベントの主要フィールド:

- `id`: 週内で一意
- `ward`: 23区の正式区名
- `name`
- `url`: 基本の参照URL
- `official_url`: 公式ページ。なければnull
- `source`: 発見・確認元
- `image`: 画像URL。なければnull
- `period`: 表示用期間（既存コピペ互換）
- `date_start`, `date_end`: ISO日付
- `time`
- `venue`
- `price`
- `description`
- `categories[]`
- `family_fit.grade`, `family_fit.reason`, `family_fit.age`
- `reservation.required`, `reservation.note`
- `indoor_outdoor`: indoor / outdoor / mixed / unknown
- `ai.checked_at`, `ai.confidence`, `ai.discovery_query`

## 6. 重複排除

URLだけでなく、以下を併用する。

- canonicalized official URL
- イベント名の正規化文字列
- 開催日
- 会場

同一イベントが複数媒体で見つかった場合、イベントは1件に統合し、`source` は最も信頼できる確認元を優先する。必要なら `sources[]` に複数保持できるよう将来拡張する。

## 7. コピペ契約 v1

利用者が最重要視するため、AIデータモデルと切り離して互換契約として固定する。

出力順:
1. タイトル
2. 場所
3. 日時
4. 料金
5. 説明
6. 公式サイト
7. 情報元サイト
8. 画像URL（存在時のみ）

一覧・コピペ画面は共通の `filterEvents()` を使用する。indexからcopyへ遷移するとき、現在の `date`, `ward`, `q` をクエリパラメータとして渡す。

AI評価、カテゴリ、予約情報等はコピペ契約 v1 の本文へ混ぜない。

## 8. 公開前検証

`python tools/validate_data.py --strict site/data` が失敗したらデプロイしない。

主な失敗条件:
- 23区のcoverageが欠ける
- `checked` でない区がある
- 不正な区名
- 必須キー不足
- URL形式不正
- 重複ID
- 明白な重複イベント
- published_count不一致
- sampleフラグがtrue

さらに `node tests/copy_contract.test.mjs` でコピペ順・フォールバックを固定する。

## 9. 現行サイトとの分離

現行 `tokyo-weekend-events` の root `site/` と root `.github/workflows/deploy.yml` は変更しない。

新サイトは別リポジトリ `tokyo-family-events-ai` を想定。現在は安全のため `prototype-ai-family-events/` に完全隔離して実装する。
